# コメント規約

## 目的

後続の読み手（Claude を含む）は渡された情報からしか判断できない。
コメントはクレート・モジュール視点での役割と、他クレート・他レイヤとの文脈を埋め込み、
ファイル単体で文脈が伝わる状態にする。

## 何を書くか

- このクレート・モジュール・関数の役割と責務境界（1〜2 行要約をドキュメンテーションコメントで）
- 呼び出し元・呼び出し先の文脈（「プラットフォームレイヤから呼ばれる」「描画バックエンドへ委譲する」等）
- 他クレート・他レイヤとの契約（共通コア ⇔ 最適化レイヤのインターフェース・前提条件）
- 非自明な前提・副作用・エラー処理の意図
- `unsafe` ブロックの `// SAFETY:` 根拠（coding-rust.md 参照）
- spec との対応（該当する REQ-N / TASK-N.M があれば言及する）

## 何を書かないか

- コードを読めば分かる逐語説明（`i += 1;  // i をインクリメント` 等）
- 陳腐化しやすい実装詳細の重複（コードと 2 重に管理しない）

## ドキュメンテーションコメントの形式

- Rust: 公開 API・モジュールに `///`、クレートルートに `//!` を付ける
- クレート・モジュール・公開 API の入口には必ず 1〜2 行の役割要約を付ける
- 本文は日本語で書く（japanese-style.md 参照）。`# Examples` 等の rustdoc 慣例セクション名は英語のまま
- Swift（SwiftUI バインド側）: `///`、TypeScript / JavaScript（Web 側補助コード）: `/** */` を使う
