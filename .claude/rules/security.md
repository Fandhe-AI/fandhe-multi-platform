# セキュリティ規約

## 秘密情報の混入防止

- API キー・トークン・パスワード・署名鍵・証明書をリポジトリ・コミット・hooks・CI 設定に含めない
- `.env` 系ファイルは `.gitignore` に含め、コミット前 diff で混入を確認する（create-commit スキルが検査）
- 署名・配布関連のシークレットは GitHub Secrets（CI）またはローカルのキーチェーン経由でのみ参照する
- ログ・エラーメッセージにシークレットを出力しない
- スクリプトは秘密情報を引数（コマンドライン引数・Gradle の `-P`）で受け取らず、環境変数
  （`FANDHE_<PLATFORM>_<ITEM>` 形式）で受け取る。未設定・部分設定は処理開始前に明示的に失敗させ、
  無署名で成功させない。エラーメッセージに値を含めない
- CI で秘密情報を一時ファイルへ展開する場合は `RUNNER_TEMP` 配下に作り、
  ジョブ終了時に必ず削除する（codex review の self-hosted runner はジョブ間で環境を共有する）。fork からの `pull_request` では
  Secrets を参照するジョブを実行しない
- 値をチャット・Issue・PR に貼らない。共有はアカウントごとの招待で行い、認証情報そのものを配らない
- 漏洩・保持端末の紛失・保持者の離任時は、値の削除ではなく**発行元で先に失効**させて再発行する。履歴からの除去は
  失効の後に検討し、失効の事実・日時・原因を（値を書かずに）Issue に残す
- 具体的な保管場所・インベントリは非公開の運用記録で管理する

## OWASP Top 10（該当項目の適用）

フレームワーク本体・配布パイプラインに関連する主な項目:

- **A02 暗号化の失敗**: 通信は TLS 前提。独自暗号を実装しない
- **A03 インジェクション**: 外部入力（URL・ファイルパス・IPC メッセージ）を検証せずコマンド・クエリへ展開しない
- **A05 セキュリティ設定ミス**: CI・ストア提出設定でのデバッグフラグ・過剰権限を残さない
- **A06 脆弱な依存**: 依存クレートの既知脆弱性を確認する（`cargo audit` 導入後は CI で実行）
- **A08 整合性の不備**: OTA 更新（Web 限定）は署名検証を必須とする

## メモリ安全性

- `unsafe` の取り扱いは coding-rust.md に従う（forbid 原則・SAFETY コメント・最小範囲）
- security-auditor は `unsafe` の新規追加を必ずレビュー対象とする

## レビュー運用

- PR 作成前に security-auditor によるチェックを通す（create-pr スキルに組み込み済み）
- critical / high の指摘がある場合はコミット・PR を中止し、ユーザーへ報告する
